# Angel Canela

Software engineer in London, working on **lego.com**. I build web experiences and help improve the architecture and tooling behind a large storefront.

I enjoy working where **product, architecture, and engineering meet**: finding clear boundaries in complex systems, understanding trade-offs, and making changes that hold up beyond the first release. My work spans shared frontend architecture, federated GraphQL, build pipelines, performance, accessibility, and developer experience.

Outside work, I build personal projects to explore the whole journey from an idea to a working product, including the data model, interface, testing, and deployment. I'm also exploring AI and coding agents as development tools, with an emphasis on reviewing and validating what they produce.

### Selected work

[**FitnessJourni**](https://github.com/angelknla/FitnessJourni) — shared fitness tracking and training sessions for friends. Handles group permissions, consistent sharing when memberships change, and optimistic updates that recover from failed saves.

[**Caelum**](https://github.com/angelknla/Caelum) — an astrology app with server-side chart calculations, interactive visualisations, and journaling. Handles historical timezone edge cases and incomplete birth details, with versioned calculations and reference tests for the engine integration.

[**Pixelar**](https://github.com/angelknla/pixelar) — a personal backlog for games, films, and TV. It brings together multiple metadata providers, imports that let users review uncertain matches, and release reminders, while preserving manual edits and handling provider failures.

**TravelBlog** — a shared travel scrapbook for trips, itineraries, and photo journals. Built around editable content, responsive image delivery, and revision checks that prevent one person's save from overwriting another's changes.

[**Portfolio**](https://github.com/angelknla/portfolio) · [angelcanela.com](https://angelcanela.com) — my personal site, built with Next.js, React, and TypeScript. Combines static delivery and multilingual content with browser games and a booking demo with accessible controls.

### How I like to work

I care about the things that make software **better to live with six months later**: clear ownership, understandable code, meaningful tests, accessibility, and changes that are safe to ship. I try to make trade-offs visible, test the failure paths, and keep the solution proportionate to the problem.

I like digging into problems that don't have an obvious answer, learning from the people around me, and sharing what I learn through reviews and documentation. Good engineering, to me, includes making the next person's work easier.
